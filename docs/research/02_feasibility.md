# 02 — Technical Feasibility Analysis & Verdict

## 1. Executive Verdict

**VERDICT: `CONDITIONAL GO` (Approach B — Hybrid Static Recompilation + Targeted Game Overrides & IOP Emulation)**

`Rule of Rose` (`SLUS-21448`, NTSC-U v1.00) is an unusually strong candidate for static recompilation on `ran-j/PS2Recomp` (`e5636981a1c9de368f6b71e819c3dc188dfedbf4`) because:
1. **Zero EE Code Overlays**: Every line of EE R5900 game, engine, scripting (`ELFR101` interpreter), 3D (`mw/i3d`), and sound (`mw/sound`) code is statically linked into a single `2,296,472`-byte executable (`SLUS_214.48`). All `.RPK` (`RTPK`) and `ELFR101` files on disc are pure data/bytecode interpreted by `CSequenceCode` (`0x001AE570`–`0x001B0CF0`), never native MIPS machine code.
2. **Rich Embedded & Verified Symbol Metadata**: Although `.symtab` is stripped, `SLUS_214.48` retains **1,795 ELF sections**, including **1,449 `.gnu.linkonce.t.*` function sections** with original GCC2 mangled C++ names and exact byte sizes, **284 `.gnu.linkonce.d._vt$*` C++ virtual tables**, `.ctors`/`.dtors`, `.eh_frame`, and **648 Sony SDK/libc/libgcc functions** (`0x0024B490`–`0x00280E88`), plus an exact SHA-1 match (`f9abd6dc53070750dfcae3b44184fb9852e603fb`) against community symbol address catalogs (`~8,963` total functions).
3. **Locked 29.97 FPS (30 Hz) Engine Design**: `MagSystem` (`0x00117654`) sets `m_v_rate = 2` (waking the main loop every 2nd VSync = `33.37 ms/frame`), giving a 2-core/4-thread Intel Core i5-7200U (`3.10 GHz`) and Intel HD Graphics 620 (`Mesa 26.0.8`) twice the per-frame CPU/GPU budget of a 60 FPS title.

The verdict is **CONDITIONAL GO** (rather than unconditional) because four specific technical blockers discovered during Argon's code audit will cause immediate compilation failure, OOM kill, or boot/input hang if not addressed in Milestones M02–M08:
1. **`.vutext` Marked `SHF_EXECINSTR` (`AX`) in `SLUS_214.48`**: Section `[1406] .vutext` (`0x00291230`–`0x002953B0`, 16,768 bytes of VU1 microcode) has the ELF `SHF_EXECINSTR` flag set. `ElfParser::isExecutableSection()` (`ps2xRecomp/src/lib/elf_parser.cpp:694`) treats any `SHF_EXECINSTR` section as R5900 code unless `.vutext` is filtered out.
2. **Stripped `.symtab` vs `.gnu.linkonce.t.*` Sections**: `ElfParser::loadSections()` only extracts functions from `.symtab`. Without feeding a complete function boundary list (`~8,963` functions across `.text` and `.gnu.linkonce.t.*`) into `ps2xRecomp`, the recompiler will miss virtually all functions.
3. **`libpad2` / `libdbc` / `libvib` Controller Stack (`BedPad`, `0x00101AEC`)**: `Rule of Rose` does NOT use legacy `libpad` (`scePadPortOpen`/`scePadRead`). It uses `sceDbcInit`, `scePad2Init`, `scePad2CreateSocket`, `scePad2GetState`, `scePad2Read`, and `sceVibSetActParam`. `ps2xIOP/src/modules/dbcman.cpp` currently stubs all RPCs except `kRpcCheckVersion = 0x80001363`, and `ps2xRuntime/include/ps2_call_list.h` only lists `scePad*`, not `scePad2*`.
4. **Host Resource Limits (`15 GiB` RAM with `0 B` Swap, and `1.1 GiB` Free on `/`)**: Compiling all ~8,963 recompiled functions in `single_file_output = true` mode or with unbounded `ninja` parallelism will trigger the Linux OOM killer; writing temporaries to `/tmp` will fill `/`.

## 3. Comparison of Candidate Architectural Approaches

### Approach A: Pure Upstream `ps2xAnalyzer` + `ps2xRecomp` Out-of-the-Box (Single-File Output, Unmodified Runtime)
* **Description**: Run `ps2xAnalyzer` heuristics on `SLUS_214.48`, run `ps2xRecomp` with default `single_file_output = true`, and link against unmodified `ps2xRuntime`.
* **Why It Fails**:
  1. `ElfParser::isExecutableSection()` marks `.vutext` (`0x00291230`–`0x002953B0`) as R5900 code (`SHF_EXECINSTR`), corrupting codegen with 64-bit VU1 microinstructions decoded as R5900 MIPS.
  2. `ps2xAnalyzer` heuristic scanning misses mid-function entry points and does not parse the 1,449 `.gnu.linkonce.t.*` section headers when `.symtab` is stripped.
  3. `single_file_output = true` generates a ~100+ MB C++ source file that exceeds `15 GiB` RAM (`0 B` swap) under `g++ 15.2.0` and triggers an OOM kill.
  4. `BedPad` (`sceDbcInit` / `scePad2CreateSocket` / `scePad2Read`) fails or blocks forever because `dbcman.cpp` only implements `kRpcCheckVersion` and `Pad.cpp` only hooks `scePad*` (`libpad`), not `scePad2*`.

### Approach B: Hybrid Static Recompilation + Targeted Game Overrides + IOP Emulation (RECOMMENDED)
* **Description**:
  1. Filter `.vutext` (`[0x00291230, 0x002953B0)`) out of R5900 executable code ranges in `ps2xRecomp` / `ps2xAnalyzer`.
  2. Build a complete, deterministic function map (`~8,963` functions) combining the 1,449 `.gnu.linkonce.t.*` ELF section headers, 284 `.gnu.linkonce.d._vt$*` vtables, 648 `sce_symbol_database_data.h` SDK symbols, and verified `.text` function starts (`0x00100000`–`0x0024B490`).
  3. Emit recompiled C++ in **32–64 unity batch `.cpp` files** (`single_file_output = false` + CMake unity batching) compiled with `ninja -j2` to stay well under the 15 GiB / 0 swap ceiling.
  4. Register `SLUS_214.48` (`CRC32 0x8cf7b024`, entry `0x00100008`) in `ps2_game_overrides`, binding `scePad2*`/`sceDbc*`/`sceVib*` to `ps2_stubs::Pad`, binding SDK stubs (`sceGs*`, `sceDma*`, `sceCd*`, `sceMc*`, `sceMpeg*`, `sceSif*`), ensuring `T0_COUNT` (`0x10000000`) and `sceGsSyncVCallback` advance deterministically, and running `LIBSD.IRX` + `RXSNDDRV.IRX` in `ps2xIOP`'s `IopEmulator` (with HLE fallback if needed).
* **Why It Succeeds**: Preserves 100% static R5900 recompilation for all game/engine/`mw::i3d`/script code while eliminating SIO2 wire-protocol dependencies, OOM compilation hazards, and `.vutext` mis-disassembly.

### Approach C: Heavy High-Level Replacement of Game Subsystems (`mw/i3d`, `CSequenceCode`, `MagSystem`)
* **Description**: Replace the game's internal 3D engine (`mw/i3d`), script interpreter (`CSequenceCode`), or scene manager (`MagSystem`) with custom C++ re-implementations.
* **Why It Is Rejected**: Unnecessary, error-prone, and risks violating clean-room boundaries. `PS2Runtime` already has working `VU1Interpreter`, `ps2_vif1_interpreter`, `GS` (`gs_cpu_backend`), and `EeScheduler` implementations that execute the game's native `mw/i3d` DMA packets and `VU1` microprograms directly.

## 4. Explicit Stop / Pivot Criteria for Flash Worker

Flash must follow Approach B through Milestones M00–M12 and trigger `gemini_flash/Gemini_Recovery_And_Debugging.txt` if any of the following conditions occur:
1. **Disk Guard**: Free space on `/` drops below `800 MiB` (`df -h /`). Immediately clean `/tmp` and verify `TMPDIR=/mnt/6421-8598/building/RozuRecomp/out/tmp`.
2. **Memory Guard**: Any `g++` or `ld` process exceeds `8.0 GiB` RSS (`Swap: 0B`). Immediately reduce unity batch size (e.g., from 64 to 128 batches) or lower optimization from `-O2` to `-O1` for generated guest functions.
3. **Missing Function Target (`[guest-branch:missing-target]`)**: Never enable `MissingFunctionPolicy::SkipCallDebug` (`3`) to fake progress. Always inspect the reported `target=0x...` and `source=0x...`, add the missing function boundary to the TOML config, regenerate, and rebuild.
