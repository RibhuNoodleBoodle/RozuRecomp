### PLAYBOOK 2: `[guest-branch:missing-target]` or `Error: No exact recompiled function for guest PC 0x...`
1. Read the full diagnostic line printed by `PS2Runtime::reportMissingFunction()` (`ps2xRuntime/src/lib/ps2_runtime.cpp:1278`):
   ```text
   [guest-branch:missing-target] kind=... op=... source=0xXXXXXXXX target=0xYYYYYYYY pc=... ra=... vtbl[0]=... trace=...
   ```
2. Check which region `target=0xYYYYYYYY` falls into:
   - **Case A (`0x00100000 <= target < 0x00280E88` or `0x00280E88 <= target < 0x00291230` or `0x002953B0 <= target < 0x00295EB8`)**:
     - `target` is a legitimate R5900 function entry point (or mid-function tail-call/switch target) that was omitted or merged into an earlier function in `config/slus_21448.toml`.
     - Disassemble 32 instructions before and after `target` in `out/disc/SLUS_214.48`, split the enclosing function at `target` in `config/slus_21448.toml`, re-run `ps2xRecomp`, and rebuild.
   - **Case B (`0x00291230 <= target < 0x002953B0`)**:
     - `target` is inside `.vutext` (VU1 microcode)! An R5900 indirect jump should NEVER jump into `.vutext`; inspect `source=0xXXXXXXXX` to see why a VU1 microcode pointer was passed to a CPU function pointer call.
   - **Case C (`target == 0x00000000` or `target >= 0x00295F00`)**:
     - Null or corrupted function pointer / uninitialized vtable pointer in guest RAM (`a0` / `s0`). Inspect `source=0xXXXXXXXX` and check whether an SDK stub (`malloc_r`, `sceCdRead`, `sceSifCallRpc`) returned `0` or failed to populate a buffer before `source` dereferenced it.

### PLAYBOOK 3: Hang in `MagSystem::waitVSync` (`0x00118754`) or `MagSystem::update` (`0x001182DC`)
1. Check `[run:tick]` logs in `stderr` (`pc=0x... ra=0x...`).
2. **If `pc` is inside `sceDmaSync` (`0x00252930`) or `0x00118754`..`0x00118790`**:
   - `MagSystem::waitVSync` is spinning on `while (sceDmaSync(m_dma, 1, 0))` waiting for VIF1 DMA channel 1 to finish.
   - Ensure `sceDmaSend` (`0x002526B8`) is bound in `game_overrides.cpp` to `ps2_stubs::sceDmaSend` and `sceDmaSync` (`0x00252930`) returns `0` (idle).
3. **If `pc` is blocked inside `WaitSema` (`m_v_sema`)**:
   - `vsyncHandler` (`0x00117654`) is not signaling `m_v_sema`.
   - Verify `sceGsSyncVCallback` (`0x00253E58`) is bound in `game_overrides.cpp` and that `EeScheduler` invokes the registered VSync callback every VSync tick (`60 Hz`) so `iSignalSema(m_v_sema)` wakes `WaitSema` every `m_v_rate = 2` VSyncs.
4. **If `pc` is spinning in a timing loop reading `0x10000000`**:
   - `PS2Memory::read32(0x10000000)` (`*T0_COUNT`) is returning a constant value (`0`). Ensure `PS2Memory::readIORegister(0x10000000)` increments with EE execution cycles.
